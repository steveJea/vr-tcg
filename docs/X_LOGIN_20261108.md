# X 로그인 설정 — staging 먼저

현재 staging은 **X와 구형 Twitter 모두 OFF**여서 X 버튼이 숨겨져 있습니다. 형님이 공급자를 켜고 저장한 뒤 게임을 새로고침하면 표시됩니다. 구글/카카오와 같은 PKCE·닉네임·스토리 CH0/스타터 경로를 씁니다. 이번 작업은 운영 사이트/DB/공급자 설정을 바꾸지 않습니다.

## 형님이 하는 순서

1. [X Developer Portal](https://developer.x.com/)에서 개발자 등록 → **Project / App 만들기** → 앱의 **User authentication settings → Set up**을 엽니다. 지금은 staging용 새 앱을 권장합니다. 개발자 이용 조건/API 접근 권한은 콘솔에서 확인하고, 결제가 필요하면 먼저 판단하세요. 이번 작업에서 결제/앱 생성은 하지 않았습니다.
2. **Type of App: Web App / Automated App or Bot (Confidential client)**, **App permissions: Read**를 고릅니다. 글쓰기/DM 권한은 필요 없습니다. Supabase 공식 안내대로 **Request email from users ON**. 게임은 이메일을 필수로 쓰지 않지만, 현재 Supabase X 구현이 기본 요청 권한에 `users.email`을 포함합니다.
3. **Callback / Redirect URI**에 아래 staging 주소를 **그대로** 등록합니다. 게임 주소가 아닙니다.
   - 지금: `https://cuyqchmdcnsgzkwyclji.supabase.co/auth/v1/callback`
   - 운영은 나중에: `https://htarwisgkkphutxxnuak.supabase.co/auth/v1/callback`
   - 운영 앱을 분리하면 그 앱에 운영 callback을 등록합니다. 한 앱을 공유한다면 나중에 두 번째 callback을 추가합니다.
4. **Website URL**은 지금 `https://vr-tcg-staging.notcold.workers.dev/`로 입력합니다. 운영 앱은 나중에 `https://ag.violenceroyale.com/`를 씁니다. **Terms of service / Privacy policy URL**을 요구하면 실제 공개한 이용약관/개인정보처리방침 주소를 넣습니다. 아직 없다면 먼저 준비해야 하며 가짜 링크를 넣지 않습니다.
5. 저장 → **Keys and tokens → OAuth 2.0 Client ID / Client Secret**을 확인합니다. staging Supabase(`cuyqchmdcnsgzkwyclji`) → **Authentication → Sign In / Providers → X / Twitter (OAuth 2.0)**를 엽니다.
   - X **OAuth 2.0 Client ID** → Supabase **Client ID**
   - X **OAuth 2.0 Client Secret** → Supabase **Client Secret**
   - **Enable ON**, **Allow users without an email ON** → Save.
   - **API Key / API Secret Key / Bearer Token / Access Token을 넣는 것이 아닙니다.** Secret은 형님이 대시보드에 직접 입력합니다. 채팅/저장소/브라우저 코드로 보내지 마세요.
6. Supabase → **Authentication → URL Configuration → Redirect URLs**에 `https://vr-tcg-staging.notcold.workers.dev/`가 있는지 확인합니다. `/index.html`로도 접속한다면 그 주소도 추가합니다. 기존 Site URL/구글/카카오 설정은 유지합니다. **지금 운영 Supabase는 건드리지 않습니다.** 운영 배치 때는 `https://ag.violenceroyale.com/`, `https://vr-tcg-prod.notcold.workers.dev/`, `https://tcg.mbbs.kr/`와 실제 쓰는 `/index.html` 경로를 추가합니다.
7. 이메일 없는 프로필용 SQL은 카카오 때의 **`supabase/kakao_profile_staging.sql`을 그대로 재사용**합니다. 이미 실행했다면 추가 SQL/재실행은 필요 없습니다. 아직 안 했다면 **그 작은 파일만 staging SQL Editor에서** 실행합니다. DB 고유번호 `7703759698107299042` 검사로 운영 실행을 차단하며, 재실행해도 기존 닉네임/UUID/진행도/재화를 변경하지 않습니다. 대형 설치 SQL이나 Edge 재배포는 필요 없습니다.
8. 게임 새로고침 → **X 로그인** 확인. 기존 진행도를 유지하며 붙이려면 **기존 구글/카카오로 먼저 로그인 → 게임설정 → X 연결**을 사용합니다. **Allow manual linking**이 켜져 있어야 합니다(카카오 연결 때 켰다면 그대로). 이미 별도 계정에 속한 X는 「이미 다른 계정에 연결된 X 계정이에요.」로 안내하며, 계정을 임의로 합치거나 지우지 않습니다.

## 구형 Twitter를 써야 할 때만

기본 선택은 위 **X / Twitter (OAuth 2.0)**입니다. 해당 공급자를 쓸 수 없고 구형만 제공되는 환경에 한해 **Twitter (Deprecated)**를 켭니다.

| X Developer의 값 | Supabase Twitter (Deprecated) 필드 |
|---|---|
| Consumer / API Key | API Key (구형 UI의 Client ID) |
| API Secret Key | API Secret Key (구형 UI의 Client Secret) |

구형에서도 callback/Website URL은 동일하고 **Allow users without an email ON**을 사용합니다. 게임↔Supabase 구간은 PKCE를 유지하지만 Supabase↔X 구간은 OAuth 1.0a입니다. 두 공급자를 동시에 켤 필요는 없습니다. 둘 다 켜면 OAuth 2.0 `x`가 우선됩니다. `x`와 `twitter`는 별도 identity이므로 이미 구형으로 가입한 사용자가 있다면 공급자를 함부로 전환하지 말고 **기존 계정 로그인 상태에서 새 identity 연결/이전 계획부터** 확인하세요.

## staging 테스트

- 공급자 OFF/조회 실패: X 버튼 숨김, 구글/카카오/게스트 정상.
- 공급자 ON: 인트로·상단 계정 영역·공급자 선택창에 X 버튼 표시. 좁은 화면은 글자를 줄이지 않고 줄바꿈.
- X 신규 가입(이메일 없음 포함): 닉네임 설정 → CH0/기존 스타터 선택 → 로그아웃/같은 X 재로그인 시 진행도 유지.
- 기존 계정 → X 연결 → X로 재로그인: 같은 UUID/진행도. 이미 연결되면 연결 버튼 숨김.
- 다른 계정 소유/동의 취소/확인 실패: 구체적인 안내, 기존 세션/진행도 보존. PC Chrome/iPhone Safari 실제 OAuth 복귀는 형님의 키 설정 후 확인합니다.

## 개발 확인 기록

- 확인 시각: **2026-11-08 KST**. staging Auth `/health` = `v2.197.0`.
- 익명 `/auth/v1/settings`는 `google:true`, `kakao:true`, `twitter:false`이며 **`x` 항목을 누락**합니다. 누락을 곧바로 「미지원」으로 판단하면 OAuth 2.0을 켜도 버튼이 계속 숨겨지는 문제가 생깁니다.
- 현재 서버에는 `x` 구현이 있습니다. 익명 `/authorize?provider=x`는 「provider is not enabled」를 반환했습니다. 구글의 경우 아래 안전 탐지 요청이 예상한 PKCE 유효성 오류를 반환하고 CORS가 허용됨을 확인했습니다.
- 탐지는 `/settings`의 명시적 `external.x` 플래그를 우선합니다. 그 항목이 없는 버전에서만 `/authorize?provider=x&code_challenge_method=S256`을 조회합니다. **의도적으로 code_challenge를 빠뜨려** 활성 공급자는 `400 / validation_failed / PKCE flow requires code_challenge_method and code_challenge`에서 중단됩니다. 이 검사는 공급자 검증 뒤, OAuth flow/session 생성·토큰 발급·X 요청 **전에** 실패합니다. 쿠키/로그인 토큰을 보내거나 리다이렉트를 따라가지 않습니다. 네트워크의 이 400은 실제 로그인 실패가 아닌 설정 감지입니다.
- 예상 오류가 아닌 응답/네트워크 장애는 X를 숨기고 구글/카카오는 유지합니다. X 상태가 미확인인데 구형 Twitter로 자동 전환하면 이메일 없는 사용자가 다른 UUID로 가입될 수 있으므로 그렇게 하지 않습니다. 구형 fallback은 새 X가 OFF/미지원임이 확인되고 Twitter ON일 때만 허용합니다. 전체 조회는 4초 제한입니다. 명시적인 `external.x:false`는 탐지로 덮어쓰지 않습니다.
- 정상 PKCE code 교환은 기존 SDK가 한 번만 수행합니다. 복귀 오류를 SDK 초기화 전에 정리해 기존 세션 손실을 방지하고, 서버 `getUser()`의 UUID와 **실제 선택한 `x` 또는 `twitter` identity**로 연결 성공을 판정합니다. 구형 identity를 새 X 연결 완료로 오인하지 않습니다.
- 추가 SQL/Edge/엔진 변경 없음. 기존 이메일 없는 프로필 패치 및 카카오 연결 회귀를 함께 검증했습니다. 실제 X 승인은 사용자 대시보드 설정 후 별도 확인해야 합니다.
