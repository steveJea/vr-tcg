## 유지하는 서버 룰
- 시즌 참가 명단이 고정된 뒤 방어 덱은 해당 시즌 중 변경 불가. UI에 🔒 표시/비활성화. 버그 수정으로 시즌 잠금을 풀지 않음.
- 오늘 이미 사용한 공격 덱은 경기 스냅샷과 남은 HP가 고정됨. 편성을 바꿔 회복·교체할 수 없음. UI도 현재 경기 사용 덱 편집 잠금.
- 같은 방어 1·2 또는 공격 1·2에 같은 인재 ID 중복 금지. 내 보유 UID만 1–5장 선택. 저장 전 선택 취소는 등록 덱/인벤토리에 영향 없음.
- 위 룰이나 토벌 상한을 바꾸길 원하면 별도 밸런스 결정 필요. 이번에는 바꾸지 않음.

## 기존 staging Supabase에서 할 일
1. **cuyqchmdcnsgzkwyclji** 프로젝트의 SQL Editor 열기. 운영 프로젝트에서는 실행하지 않기.
2. `supabase/security_phase4_war_card_details.sql` **파일 전체를 한 번 실행**. DB 고유번호와 phase4 엔진 버전 가드 있음. 재실행도 안전.
3. staging 웹 새로고침 후 조직전쟁 카드 상세/덱 편성 테스트.

이 작은 SQL은 읽기 함수 `_war_side_json_v4`만 교체하여 상세용 허용 목록 메타데이터를 반환함. 보유 인재 UID·임의 추가 필드는 상대에게 노출하지 않음. HP, 시즌/경기, 시계, 덱, 횟수, 보상 등 **어떤 데이터 행도 변경하지 않음**. 기존 진행 상태를 지킬 때 seed reset이나 전체 신규 설치를 실행할 필요 없음.

**Edge 재배포 불필요.** `guildbattle-verify-v4`, `_shared`, 엔진 해시, `dashboard_single_file.ts` 변경 없음. 클라이언트 전투 규칙도 변경하지 않았음. 신규 staging 설치 SQL/14개 분할본/manifest SHA256은 같은 읽기 함수로 다시 생성함. 새 스타일은 `css/guild.css`/`css/pages.css` 커스텀 CSS이며 새 Tailwind 유틸리티는 없음. `css/tw.css`도 고정 버전 3.4.17로 재빌드함.

## 확인 방법
- 배치 기간: 내 덱 → 방어 덱 1 선택 → 인재 선택 → 취소(변화 없음), 다시 선택 → 저장(반영). 시즌 중 방어 덱 🔒 확인.
- 같은 유형 1·2번 중복 인재는 선택 불가. 이름/코스트 검색, 저장 덱 가져오기, 큰 썸네일 상세 확인.
- 공격 덱 2를 해제한 상태에서 적 아지트 → ‘공격 덱 2 편성’ → 저장 → 같은 적으로 돌아오는지, 공격 횟수 그대로인지 확인.
- 적 아지트 카드 클릭 → 현재 HP/고정 레벨/강화/역할 보정 상세가 앞에 보이는지 확인.
- 편성 창 로딩/저장 중 탑으로 이동 → 뒤늦은 전쟁 팝업이 나오지 않는지 확인.
- 토벌: ‘행동당 상한’, 반복 피해 ‘2타’, 누적 총합이 6,000을 넘어가는지 확인.
- 이전 seed의 `action := 'refill'`은 HP·방어조 파괴 진행을 유지하고 횟수만 보충함. 이번 수정으로 seed 사용법은 변하지 않음.
