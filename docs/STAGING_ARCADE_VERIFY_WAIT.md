# 아케이드 `검증 중` 대기 수정 (2026-11-08 KST)

기준 staging: `e3b081f0e7da574c98f56a09e68cc9f116409c80`.

## 후속 UX 변경

검증 동안 결과창 자체는 숨기고 전투 화면 위에 옅은 어둡힘 + 작은 스피너만 표시한다. 눈에 보이는 글자/버튼은 없음. 서버 확정 결과가 준비되면 곧바로 최종 결과창을 열며, 실패/15초 시간초과에만 기존 재시도 화면을 연다. 재시도·처음으로·새 판 시작 시 스피너를 정리한다. 서버 검증·영수증·SQL/Edge는 변경하지 않는다.

## 설치 여부: 익명/무상태 검사만 수행

테스트 프로젝트 `cuyqchmdcnsgzkwyclji`에만 공개 publishable key를 사용. 사용자 로그인/JWT/관리자 키/실제 전투 데이터는 사용하지 않음.

- `arcade-verify-v5` GET → **405 POST required**, OPTIONS → **204**. 존재하지 않는 비교 함수 OPTIONS는 **404 NOT_FOUND**. Edge 배포 자체는 확인됨.
- 현재 엔진 해시 `e792c491ffafe19d047aa6f58db1920e5767e4059e14816611dd38d473871161`로 인증 없는 시작 형식 검사 → **401 login required**. 의도적으로 틀린 해시 → **409 새 전투 버전으로 새로고침**. 버전 검사 다음 인증에서 종료되므로 세션 발급/DB 변경 없음. 배포된 Edge 엔진 버전도 현재 프런트와 일치함.
- 정확한 인자명을 사용한 GET RPC 검사: `arcade_start_v5`, `arcade_engine_session_v5`, `arcade_engine_settle_v5`, `arcade_record_v5` 모두 **401 / 42501 permission denied for function**. SQL 함수가 설치되어 있고 익명 권한은 차단된 상태. 인자를 생략한 404는 설치 누락의 증거로 사용하지 않음.
- `dev-tcg.mbbs.kr` 공개 프런트는 이 환경에서 TLS EOF, 대체 workers 공개 주소는 403으로 라이브 바이트 대조 불가. 인증된 형님 세션의 실제 요청/오류/DB 정책 값까지 확인한 것은 아님.

따라서 **SQL/Edge 미설치로 단정하면 안 됨**. 적어도 해당 함수들과 일치하는 Edge 엔진은 존재함.

## 코드에서 확인·재현한 원인

1. `functions.invoke`, 오류 본문의 `.json()`, 재시도/상태 복구에 시간 제한이 없어 한 요청만 응답하지 않아도 영원히 `검증 중`에 머무를 수 있었음.
2. **서버 정산이 성공한 뒤에도 부가 전적 조회 `loadRecord()`를 await**하고 있었음. 그 조회가 끝나지 않으면 이미 서버가 확정한 결과까지 화면에 전달되지 않음. pending 증거는 먼저 지운 상태여서 UI만 계속 대기하는 경로를 재현함.
3. 실패 원인은 토스트만 띄우고 화면에는 제대로 남기지 않았음. 도감 보류 문구와 빈 통계 배경이 섞여 검증이 계속 진행 중인 것처럼 보일 수 있었음.

형님이 본 특정 판에서 어떤 네트워크 요청이 멈췄는지는 익명 접근만으로 확정할 수 없음. 두 무한 대기 경로 모두 네트워크 없는 회귀 테스트로 재현·차단함.

## 수정

- 검증/시작 네트워크 대기는 **15초 한도**. 재시도·오류 JSON·상태 복구가 같은 한도를 공유함.
- 이미 확정된 영수증은 즉시 반환. 전적/미션 새로고침은 별도로 실행하고 그 실패가 결과 표시를 막지 않음.
- 실패하면 `검증을 완료하지 못했어요` + 원인 + **다시 시도**를 표시. 검증 전 공유/새 판 버튼은 비활성, **처음으로**는 사용 가능.
- 미확정 행동 기록/동일 세션/요청 UUID를 보존. 시간초과 후 서버가 늦게 정산했더라도 재시도하면 원래 영수증만 회수하며 중복 지급하지 않음.
- 잘못된 영수증/계정 변경을 성공으로 취급하지 않음. 클라이언트 승리로 대체하지 않음.
- 빈 통계 배경과 이전 도감 문구는 검증 대기 화면에서 숨김. **도감·MVP 반영 보류는 별도 보안 범위의 기존 정책**이며 이번에 해제하거나 지급하지 않음.
- 결과 꾸미기 렌더러가 실패해도 `검증 중`을 남기지 않고 표시 오류로 전환.

## 형님이 할 것

- **이번 수정으로 새 SQL 실행/Edge 재배포는 필요 없음.** 엔진/SQL/Edge 코드를 변경하지 않았음.
- staging 프런트 배포 완료 후 **강력 새로고침**, 로그인 상태에서 새 아케이드 한 판.
- 정상 응답은 바로 승/패 결과, 느린/끊긴 응답은 15초 후 실패/재시도로 바뀌는지 확인.
- 실패가 계속되면 화면의 오류 문구를 전달. 필요 시 같은 판의 `TCG.S.arcadeError`에 남는 trace로 Edge 로그를 조회할 수 있음(로그인 토큰이나 행동 원문 공유 불필요).
- 승인된 실제 계정/운영 데이터에는 접근하지 않았고, main/production은 변경하지 않음.
