# 피드백 시트 18–21 (2026-11-08 KST)

기준: `454f4cfd72831aa6e827c65e4807a90a3326b79b` (보안 5단계 포함).
시트 원본 및 기존 8–17 탭은 변경하지 않음.

## 반영

- **18-1** 상대가 공격할 때도 피격 카드/진영으로 먼저 스크롤. 고정된 손패/HUD를 제외한 전장 공간에 맞추고, 이동이 끝난 뒤 돌진/피격 연출을 진행한다. 아케이드와 공용 전투 뷰의 양측 일반 공격/스킬에 적용한다.
- **19-1** 등장 음성 `_0`이 사전 로딩 대상에서 빠져 있었음. 현재 손패·필드·곧 드로우할 카드의 등장 음성도 미리 준비하고, 음성 목록이 늦게 도착하면 이전 사전 로딩 요청을 이어서 처리한다. 컷인/영상 큐 순서는 그대로 유지한다.
- **20-1** 손패 일부 교체·정렬·마나 변화마다 손패 전체 DOM을 버리던 경로를 카드별 갱신으로 교체. 남아 있는 카드의 이미지 노드/디코드 상태를 유지한다. 로컬 썸네일을 먼저 준비하고, 양쪽 덱 전체의 큰 이미지·효과·음성을 동시에 다운로드하던 초기 요청을 현재 카드와 다음 2장으로 줄인다. 썸네일 준비 캐시는 최대 96장. 최초 미캐시 이미지/음성의 실제 네트워크 다운로드 시간 자체를 없애는 변경은 아니다.
- **21-1** 다시하기/처음으로를 누르면 음성을 즉시 중지. 0.5초 뒤 시작하도록 예약된 결과 대사도 취소하고, 이전 전투의 지연 콜백이 새 화면에서 재생되지 않게 검증한다.
- **21의 사본-1** 보안 5단계의 `검증 중` 화면이 승/패 배경 클래스를 모두 제거해 전투 화면이 비치던 문제. 불투명 배경을 추가한다. 서버 검증을 건너뛰거나 클라이언트 승리를 미리 표시하지 않는다. 검증 응답이 늦게 도착해도 이미 나간 결과 화면을 다시 열지 않는다.
- **연관 버그 추가** 아케이드 필드 드래그가 엔진 밖에서 배열만 바꿔 서버 재현 기록과 달라질 수 있었음. 기존 서버 지원 `move` 행동을 기록하도록 연결한다. 수비대장은 그대로 두고 일반 필드 카드만 재배치한다. 드래그가 포함된 8개 전투의 최종 결과를 변경 없는 Edge 엔진으로 재현한다.

## 배포

- SQL, RPC, 보상, 승패 판정, 서버 엔진 및 Edge Function 코드 변경 없음.
- **이 변경 때문에 새 SQL 실행/Edge 재배포를 할 필요는 없음.**
- 이전 보안 5단계의 SQL/`arcade-verify-v5`가 staging에 아직 설치되지 않았다면 그 설치는 별도로 완료해야 한다.
- 새 Tailwind 유틸리티 없음 (`end-pending`은 직접 작성한 CSS). `css/tw.css` 재생성 불필요. SQL 소스 변경이 없어 staging SQL manifest hash도 그대로 유효하다.
- staging 프런트 배포가 끝난 뒤 강력 새로고침.

## 확인할 것 (PC Chrome)

1. 아케이드 수동/AUTO: 상대 일반 공격·스킬이 내 카드/진영을 때릴 때 고정 HUD 위로 피격 대상이 보이는지.
2. 처음 뽑은 카드도 소환 전에 등장 음성이 준비되는지. 여러 컷인/영상은 기존처럼 차례대로 재생되는지.
3. 패 섞기/정렬/소환/마나 변경 후 손패 썸네일 깜빡임이 줄었는지, 새 손패 클릭이 맞는 카드 상세를 여는지.
4. 승리/패배 대사가 나오기 직전 또는 재생 중 다시하기/처음으로를 눌렀을 때 이전 대사가 끊기는지.
5. 느린 네트워크에서 전투 종료: `검증 중` 화면 뒤로 전투가 비치지 않는지. 기다리는 중 처음으로를 눌러도 늦은 응답이 화면을 되돌리지 않는지.
6. 아케이드 필드 카드를 앞뒤로 드래그한 뒤 끝까지 진행해 서버 검증/기록 저장이 통과하는지.

자동 검증: `npm run check:staging`, `npm run test:staging`, `npm run build:staging`, `npm run test:security:phase1` ~ `phase5`.
실제 브라우저 미디어 지연(다운로드/디코드 속도)은 위 수동 항목으로 최종 확인한다.
