# 보안 5단계 — 아케이드 (스테이징만)

## 형님이 할 순서
1. Supabase **cuyqchmdcnsgzkwyclji (테스트)** → SQL Editor에서 `supabase/security_phase5_arcade.sql` **전체**를 실행합니다. 기존 설치본/14분할 설치본은 다시 돌리지 않습니다. 운영 DB에서는 가드가 거부합니다.
2. 같은 프로젝트의 Edge Functions에 **arcade-verify-v5**를 새로 만듭니다. `supabase/functions/arcade-verify-v5/dashboard_single_file.ts` **전체**를 Dashboard의 index.ts에 붙여넣고 Deploy합니다. **JWT verification ON**. 별도 비밀키 입력/새 Secret 생성은 필요 없습니다. 런타임 기본 `SUPABASE_*` 값만 사용합니다.
3. `https://dev-tcg.mbbs.kr`에서 강력 새로고침한 뒤 다시 로그인합니다. 이미 진행 중이던 구버전 아케이드는 새 공식 기록에 포함되지 않으니 새 판으로 시작합니다.
4. SQL → Edge 순서 사이에는 새 아케이드 시작이 실패하도록 막혀 있습니다. 실패를 로컬 승리로 대체하지 않습니다. main/운영 반영이나 실제 Supabase 실행·배포는 이 PR에 포함되지 않습니다.

PvP / 토벌·조직전 Edge 및 그 SQL은 **이번 변경으로 재배포할 필요 없습니다**. 원본 공용 rules/skills/PvP/raid/war 코드는 그대로입니다. 아케이드 전용 `_shared/arcade-engine-v5.mjs`는 Dashboard 단일 파일에 포함됩니다.

## 바뀐 내용
- 서버가 발급한 세션/시드/설정 + 합법적인 플레이어 행동만 제출합니다. 공용 reducer가 양쪽 덱·소환·수비대장·아이템·용병·고유기술·AI·확률·턴 종료·시간제 판정을 똑같이 재생하고 결과/피해/고유기술 수/MVP를 서버에서 계산합니다.
- AUTO/수동, 전체·등급 필터, 10/40/무제한(기존 안전 상한 400 반턴), 카드 우선 설정을 지원합니다. 연출 RNG는 전투 RNG와 분리합니다. 계정 경험치/행동력 지급 규칙은 변경하지 않습니다.
- 브라우저의 `matches` 직접 INSERT 및 컬럼별 쓰기 권한을 차단합니다. 새 전적·주간/전체 랭킹·아케이드 승리 업적·미션은 새 서버 원장만 읽습니다. 게스트는 별도 **연습 전적**, 계정은 별도 **검증 전적** 캐시를 씁니다.
- **이전 matches/전적·보상은 삭제/회수하지 않습니다.** 검증 전 기록은 legacy 원본으로 보존하며, 검증할 증거가 없어 **새 공식 집계에는 합산하지 않습니다**. 따라서 새 검증 전적은 0부터 보일 수 있습니다. 과거 기록을 새 공식 기록으로 소급 인정하려면 별도 정책/검토가 필요합니다.
- 17-1의 일일/주간 아케이드 미션과 전체 완료 보상을 재개합니다. 아케이드 미션은 검증 완료 1판/7판, 승리·스킬은 실제 검증된 수만 추가됩니다. 기존 phase2/3 검증 진행도도 유지됩니다. 전체 완료는 모든 서버 목표를 충족해야 하며 중복 수령은 차단됩니다.
- 미완료 포기/만료는 서버 확정 패배이며 미션·승리·스킬 진행도는 주지 않습니다. 보류 중인 결과는 계정별로 보관해 재시도합니다. 새 판은 이전 결과를 먼저 재처리하거나 포기를 확인합니다. 세션 2시간, 발급 간격 2초, 하루 발급 상한 500판입니다(임의 시드 재뽑기 방지).
- Edge는 임의 결과·추가 필드·잘못된 JWT·타인 세션·불완전/불법 행동·버전 불일치를 거부합니다. 같은 제출은 원래 영수증만 반환하고, 다른 제출 충돌은 추가 기록/지급 없이 거부합니다.
- Edge 로그: trace/operation/HTTP status/검증 소요 ms/중복 여부/제한된 오류 코드만 기록합니다. JWT/키/행동 원문/사용자 개인정보는 기록하지 않습니다. 응답 trace와 영수증 session_id로 조사합니다.

## 테스트할 것
- 로그인 → 아케이드 수동 1판, AUTO 1판. 수비대장 배치/교체, 소환 취소, 자리 바꾸기, 아이템/회수/희생/용병, MR 영상 스킵/완주가 멈추지 않는지 봅니다.
- 등급 필터와 10/40/무제한·카드 우선 설정을 각각 시험합니다. 결과 화면은 먼저 검증 중 → 서버 확정 결과로 바뀌어야 합니다. 이전 승리/공유 내용이 검증 중에 재표시되면 안 됩니다.
- 전적/마이페이지/주간·전체 랭킹이 1판당 한 번 반영되는지 확인합니다. 전송 중 네트워크를 끊었다가 `다시 시도`/새로고침 후 재접속해도 중복되지 않아야 합니다.
- 일일 아케이드 1판 보상, 주간 7판 보상, 다른 미션까지 완료한 전체 보상이 열리는지 봅니다. 포기만 해서는 완료 수가 증가하지 않아야 합니다.
- 로그아웃 연습/다른 계정 기록이 섞이지 않는지, 유리의 특강·스토리·탑·PvP·토벌·조직전이 기존대로 동작하는지 봅니다.

자동 검사: check:staging / test:staging / build:staging / test:security:phase1–5. 60가지 설정 조합 및 40개 추가 수동 행동 시드의 브라우저·서버 일치, 실제 Dashboard 코드 + PostgreSQL ACL/영수증/미션/보상/킬스위치 검사를 포함합니다. 실제 Google OAuth·모바일 터치·오디오/영상·실시간 네트워크 장애는 스테이징에서 형님 확인이 필요합니다. 이 단계 통과만으로 운영 보안 전체 검토/운영 승인을 대체하지 않습니다.

```sql
-- 운영 프로젝트에서 실행하지 않도록 세션에서 확인 후 사용합니다.
do $$ begin
 if (select system_identifier::text from pg_control_system()) <> '7703759698107299042' then
  raise exception 'STOP: staging only';
 end if;
 update public.arcade_policy_v5 set enabled=false where singleton;
end $$;
```
신규 시작과 미완료 정산, 아케이드/전체 미션 수령을 보류합니다. 이미 확정된 원장/보상은 삭제하지 않습니다. 재개는 같은 staging 가드 안에서 `enabled=true`로 변경합니다. **마이그레이션 재실행은 disabled 상태를 자동으로 켜지 않습니다.** 구버전 raw matches 쓰기를 되살리는 롤백은 금지합니다. 향후 엔진 변경 전에는 진행 중 아케이드를 종료하고 SQL 해시 → 새 Edge → 웹 새로고침 순서를 맞춥니다.
