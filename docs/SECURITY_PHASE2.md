# 보안 2단계 — 세션 프로토콜 초안 / 미완료

작성: 2026-11-07 KST. **2단계 완료 아님. 소유자에게 SQL 실행이나 배포를 요청하지 않는다.**

## 현재 결과

- `security_phase2_clears.sql`은 **shadow-only** 서버 세션 프로토콜이다. 기존 RPC,
  클라이언트, 전투 룰, 잔액, 진행, 행동력은 변경하지 않는다. 실제 DB 적용 없음.
- 시작 토큰·서버 seed·서버 스냅샷·소유권·요청 중복·순서 게이트·크기/턴 범위·만료와
  제출 이력만 구현했다. 이것은 **실제 전투 승리 검증이 아니다.**
- `finish`는 `submitted`까지만 전이한다. `verified/settled` 전이·지급 함수는 없다.
  `ok:true`는 프로토콜 요청 성공일 뿐이며 반드시 `shadow:true`, `reward_held:true`,
  `verification:replay_not_installed`가 함께 반환된다. 지급 성공으로 취급하면 안 된다.
- **새로 해제된 보상: 없음.** 튜토리얼 10티켓/400젬, 챕터 티켓/젬/별 보상,
  스토리 전투 미션, 탑 보상은 여전히 1단계와 같이 보류다.
- PvP 연승/등급/시즌 및 토벌·조직전/조직 미션 보상도 여전히 보류(3~4단계).
- 기존 `story_complete_phase`, `story_set_stars`, 소탕 등의 무검증 진행/EXP 경로도
  아직 교체하지 않았다. 이 SQL은 그 경로의 보안을 완성하지 않는다.

## 검증기 없이 지급을 열지 않은 이유

`FIX_PLAN.md` 공통 B 및 2단계는 수동 전투의 행동 의도를 서버에서 재실행하여
승패·턴·마나·출전·처치·막기·별을 산출하도록 요구한다. 토큰, seed, 몇 초 경과,
1~40턴, 그럴듯한 JSON 검사만으로는 기다린 뒤 위조한 승리를 구분할 수 없다.

현재 전투는 `js/game.js`의 브라우저 전용 경로이고, `quest-sim.js`는 별도의
자동 소탕 규칙이다. `pvp-core.js`는 손패/소환/제한 마나/스토리 난입/불사/생존
조건을 포함한 스토리 엔진이 아니다. 이를 그대로 대체하면 게임 느낌·결과가 달라진다.
이번 변경에는 이 엔진을 이식·배포하는 작업이 들어 있지 않다.

따라서 이 초안으로 지급을 재개하거나, 단계별 검증 완료라고 안내하면 안 된다.
일반 사용자 JWT로 결과를 인증하거나 `verified=true`를 전달하는 우회 RPC도 없다.

## 구현된 프로토콜

공개 API는 `authenticated`만 호출할 수 있고 사용자는 `auth.uid()`로 정한다.

| RPC | 용도 |
|---|---|
| `battle_session_start_v2(text,text,jsonb,uuid)` | 모드/대상/출전 uid 배열/요청 UUID → 불변 세션 발급 |
| `battle_session_finish_v2(uuid,jsonb)` | 행동 배열 제출. 전투 검증/지급 없음 |
| `battle_session_status_v2(uuid)` | 본인 세션 상태 조회 |
| `battle_session_abort_v2(uuid)` | 미제출 shadow 세션 종료. 비용/환불 없음 |

- 대상 정규형: tutorial `1`, story `0:1`, tower `normal:1`. 숫자 별칭 거부.
- 단계/층 해금은 새 `battle_clear_receipts_v2`만 참조한다. legacy 클리어/별/층은
  복사하지 않는다. 영수증 생산자가 아직 없으므로 정상 진행도 다음 단계로 갈 수 없다.
- 실제 보유 인스턴스의 스탯/레벨/스킬/장비는 기존 비공개 `_pvp_snap`으로 DB에서
  읽는다. 튜토리얼 편성/대본은 서버 테이블에 고정한다. 스토리 필수/게스트/대여
  편성, 적 생성/스테이지 전체 룰의 확정은 **아직 미구현**이다.
- 계정당 활성 세션 1개, 계정/요청 UUID unique. 같은 요청은 같은 토큰/스냅샷,
  같은 제출은 같은 상태를 반환하며 다른 대상/출전/행동으로 재사용하면 거부한다.
- 계정/모드/스테이지/룰 버전의 seed를 재시도·포기·만료에도 유지한다.
  seed와 UUID는 전투 증명이 아니며 서명으로 사용하지 않는다.
- 서버 시각으로 2시간 만료, KST 일별 500회 **shadow 발급** 상한. 이 수치는
  실게임 비용/시도 정책으로 채택된 것이 아니다. 제출된 증거는 지우거나 교체하지
  않는다. 제출 세션이 활성 슬롯을 유지하므로 이 초안을 실게임에 연결하면 안 된다.
- 행동은 2,000개/256KiB 이내, 단조 증가하는 1~40턴 등 전송 한계만 검사한다.
  리소스·대상·스킬 합법성, RNG 재생, 승리 증명은 없다.
- 새 테이블은 RLS+테이블/열 SELECT/쓰기 모두 API 역할에 차단한다. helper 및
  같은 이름의 다른 overload도 EXECUTE를 회수하고 4개 시그니처만 공개한다.
- 기존 데이터/원장/보상 이력 리셋·회수·자동 소급 지급 없음.

## 남은 구현 (완료 조건)

1. DOM 없는 **공유 전투 엔진**과 행동 프로토콜: 자동/수동 모두 기존 게임과 같은
   RNG·반올림·마나·스킬·난입·부활·불사·생존·패배 클리어 조건을 재현해야 한다.
2. 서버 런타임 선택/구현. DB 내 검증이 아니라 서버 엔진이면 인증 JWT 검증 및
   최소권한 정산 경계를 마련하고 서버가 직접 재생한 결과만 DB에 확정한다.
   비밀값은 소유자 콘솔에서만 관리하며 대화/저장소/브라우저에 전달하지 않는다.
3. 출전/게스트/필수/대여/장비/적 스냅샷과 버전/카탈로그 해시 일치. 입장 비용
   예약 및 실패/만료/중단 정책을 구현한다. 기존 정책을 임의로 바꾸지 않는다.
4. `issued → submitted → verified → settled` 원자적 정산, 서버 별/EXP/드롭/진행/
   미션 이벤트, 기존 수령 이력까지 참조하는 정확히 한 번 지급.
5. 공개 구형 완료/별/소탕/overload/직접 테이블 우회 폐쇄. 검증된 과거 클리어만
   소탕 자격으로 사용하고 미검증 legacy 소급/재지급은 하지 않는다.
6. 튜토리얼·스토리·탑 UI를 새 시작/행동/결과 경로에 연결하고 실제 서버 결과만
   표시. 게스트 기록을 계정 승리로 자동 인증하지 않는다.
7. 정상 전투 golden fixture, 조작/동시 요청/재연결/기간 경계/폰 테스트 후에만
   해당 지급 보류를 해제한다.

## SQL 순서 / 설치본

**지금은 실행 요청하지 않는다.** 향후 완성본의 기본 전제 순서는:

1. `security_phase1_preflight.sql` (읽기 전용)
2. `security_phase1_rewards.sql` (이미 적용했다면 다시 설치할 필요 없음)
3. `security_phase2_clears.sql` (**현재는 미완료 초안**)
4. 아직 작성되지 않은 실제 replay/정산 migration + runtime + client

초안은 `tools/staging_sql_sources.json`에서 명시적으로 제외하여 자동 신규 설치본에
들어가지 않는다. 완성 후 이 제외를 해제하고 설치본/분할본을 재생성·검증해야 한다.
어떤 단계에서도 보안 플래그만 켜거나 옛 보상 SQL을 재실행하지 않는다.
