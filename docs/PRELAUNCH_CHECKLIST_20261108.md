## 4. 실제 코드에서 확인한 것 — 오해 방지

1. **보안은 상당히 진전됐지만 ‘전부 끝’은 아니다.** [SECURITY_PHASE2](SECURITY_PHASE2.md#보장과-한계)는 기다린 뒤 그럴듯한 결과를 내면 통과할 수 있음을 명시한다. 현재 SQL 응답도 `validation: plausibility-v3`다. PvP/토벌·조직전/아케이드 재현과 같은 수준이라고 홍보하면 안 된다. 서버 재현도 합법적 행동을 자동 수행하는 봇·다계정·담합까지 막아 주지는 않는다.
2. **도감 전체가 막힌 것은 아니다.** `js/gallery.js:91–94`는 아케이드 종료 때 ‘도감·MVP 반영 보류’를 표시하고, `gallery_register`는 보류다. 반면 서버 검증 획득 이력에 기반한 소환/스토리 획득 도감·일부 수집 보상은 별도 경로다. phase5 공식 MVP 기록이 있다고 왕관/도감 보상이 자동 연결되는 것은 아니다. 남은 항목별 지급/미제공 정책을 정리해야 한다.
3. **결제는 아직 없다.** `js/gem.js:58–62`는 ‘충전은 준비 중’만 표시한다. `supabase/gem.sql:23–35,74–103`의 유/무료 젬 분리·원장·중복 참조는 좋은 기반이나 PG 주문/승인/환불 시스템 완성이 아니다. 현재 원장 unique는 `(user_id,ref)`이므로 결제 주문 소유자·전역 중복 방지는 새 주문 모델에서도 강제해야 한다.
4. **‘스킨 위주 BM’과 ‘성장 과금 없음’은 다르다.** 젬 상점에는 소환권 150/10회 1500, 행동력 100부터 일일 상승, PvP 추가 도전 50, 골드가 있다(`gem.sql:50–55`). 유료 젬을 팔면 현재 코드상 성장/해금 속도·도전 횟수에 영향이 있다. 과금 혜택과 랭킹 공정성 원칙을 먼저 명시한다.
5. **확률 버튼은 이미 있으나 충분성 확인이 필요하다.** `js/story.js:1947–1950`은 등급별 합계와 10회 HR 이상 보장 문구를 보여 준다. `gacha_premium_ur.sql:28–45`는 초회 하지은 확정·10회 조건부 보장·UR 고정 풀을 사용한다. 카드별 확률·제외 카드·보장 조건/해당 확률, 강화/합성 등 다른 유료 연계 랜덤 결과도 대조하고 검색 가능한 공개표·버전 이력을 갖춘다.
6. **운영 도구는 일부 있다.** `admin.sql`은 인증된 관리자 이중 확인, 조회·지급·감사 로그를 제공하고 `trade_admin.sql`은 의심 거래·강제 취소/환불을 다룬다. 다만 사용자 탈퇴·신고/정지 전체 흐름·CS 결제 대사는 찾지 못했다. `admin_reset.sql:20–26`의 고정 구테이블 목록은 보안 v2~v5 새 영수증과 정합성 점검이 필요하므로 상용 CS에서 초기화 버튼을 관성적으로 쓰지 않는다.
7. **약관·개인정보·환불·등급 표시는 저장소 탐색에서 찾지 못했다.** 별도 외부 문서/등록이 없다고 단정하지 않는다. Google OAuth는 PKCE지만 로그인 동의가 게임 약관/필요한 개인정보 동의를 대신하지는 않는다. `index.html:273–279`는 GA4를 기본 로드한다. 분석 처리의 고지/법적 근거/동의·거부와 국외 이전·보유기간은 전문가와 정한다.
8. **로그가 아예 없는 것은 아니다.** 아케이드 Edge handler는 trace/상태/소요 시간 로그가 있고 클라이언트는 15초 제한·같은 영수증 복구가 있다. 하지만 JS 오류 수집/게임 퍼널·운영 알림의 연결은 코드에서 찾지 못했다. PvP/토벌·조직전까지 공통 요청 ID로 CS 추적 가능하게 한다.
9. **자산은 큰 편이다.** main 추적 파일 3,382개 약 360.9 MiB, 웹 배포 허용 목록 기준 2,985개 약 351.0 MiB. 전체 MP4 46개 약 112.7 MiB, MP3 586개 약 84.0 MiB, WEBP 2,212개 약 150.9 MiB. 이는 **첫 접속 다운로드량이 아니다.** 최댓값은 오프닝 MP4 약 17.74 MiB. 실제 cold/warm cache 전송량·요청 수·FPS·메모리를 기기에서 측정한다.
10. **일부 외부 의존성이 남는다.** 카드 이미지의 다른 GitHub 저장소 `/main/` raw 주소, jsDelivr의 Supabase SDK, Google Fonts/GA 등이 있다. 권리 확인 후 통제 가능한 버전/CDN 경로를 사용하고 SDK 업데이트·DOM/XSS·보안 헤더를 점검한다. CORS/홈페이지 WAF/숨긴 버튼은 직접 Supabase API 조작 방어를 대신하지 않는다. 이번에 XSS나 새 잔액 변조를 재현한 것은 아니다.
11. **콘텐츠 수보다 도달 시간 검증이 중요하다.** 실제 `index.html` 순서대로 스토리 데이터를 로드하면 CH0~15, 기본 페이즈 합계 **206개**다. 기본 6행동력×10 EXP와 최초 일반 50/보스150 보너스를 각 페이즈 1회 적용한 단순 계산은 CH0+1 **1,300 EXP → Lv4**, CH0~15 **23,760 EXP → Lv25**다. 실패·반복/소탕·추가 행동력 사용에 따라 달라진다. Lv40 누적 필요량은 56,160 EXP라 빛/어둠까지 추가 32,400 EXP가 필요하다. **EXP 원천을 추가하자는 제안이 아니라** 기존 반복 플레이가 재미있는지 검증하자는 뜻이다.
12. **탑은 일반 1종 + 속성 5종, 총 6종**이고 공통 층 데이터는 350층이다(`js/quest.js:23–26`, `data/quest.json`). 반복/속성 변형 2,100층이 2,100개의 서로 다른 수제 콘텐츠를 의미하지는 않는다. 스토리 각 루트의 대사·연출·필수 캐릭터·보스 조건, 첫 30일의 실제 플레이 시간을 검수한다.
13. **기존 테스트 기반은 좋다.** `package.json`에 staging·보안1~5·production 검사들이 있다. 다만 저장소에 `.github/workflows`는 없고, 직전 main 릴리즈의 GitHub 검사는 Pages 배포뿐이었다. 원격 브랜치 보호 설정은 이번에 조회하지 않았다. PGlite/VM 테스트는 실제 Postgres 병렬성·기기·OAuth/PG 검증을 대신하지 않는다.

## 5. 결제/법률에서 특히 놓치지 말 것

- **토스페이먼츠 직접 vs 포트원:** 토스는 PG 직접 연동, 포트원은 여러 PG를 연결하는 결제 인프라다. 국내 웹에서 1개 PG로 시작할지, PG 교체/복수 채널이 곧 필요한지로 고른다. **포트원을 쓰면 PG 심사/계약·게임업종 승인/환불/법적 의무가 사라지는 것은 아니다.** 수수료·정산주기·보증보험/한도·가상재화 취급 가능 여부는 실제 견적으로 확인한다. 지금 양쪽을 모두 구현할 필요는 없다.
- **첫 판매는 단순하게:** 젬 충전 1~2개 SKU, 자동 갱신 없는 상품부터. 주문 금액·통화·상품·상점·계정은 서버 저장값으로 확인하고, 성공 URL/브라우저 콜백만으로 지급하지 않는다. 서명 지원 웹훅은 해당 규격으로 검증하고 PG 서버 조회로 금액/상태를 대조한다. PG의 멱등키와 **게임 DB의 영구 중복 방지**는 둘 다 필요하다.
- **미성년/개인정보:** 이용 가능 연령, 법정대리인 동의가 필요한 아동 개인정보/미성년자 계약, 연령 확인 수단을 등급/정책과 맞춘다. 개인정보 처리방침에는 실제 수집 항목·목적·보존·위탁/국외 이전·삭제/문의 절차·분석 도구를 반영한다. 한국/해외 서비스 범위에 따라 별도 요건이 달라지며 일률적인 해외형 쿠키 배너만으로 해결하지 않는다.
- **확률 공개:** 게임산업법 제33조와 시행령 제19조의2/별표3의2 기준으로 적용 범위를 검토한다. 소규모 등 예외가 있을 수 있지만 신규 사업의 환산 매출 등 조건까지 확인해야 하므로 ‘작으니 자동 면제’라 하지 않는다. 설령 예외라도 실제 확률 공개를 권한다. 젬→소환권처럼 **간접 유료 랜덤 경로**도 검토 대상이다.
- **환불/청약철회:** 통상 7일 철회 원칙과 디지털콘텐츠 제공 개시 예외·고지/체험 조건·미제공 분할분·미성년자 취소·오표시를 구분한다. **‘젬을 받았으니 일절 환불 불가’라는 문구만으로 끝내지 않는다.** 무료/유료 젬 소비 순서, 보너스 젬/부분 환불, 사용한 스킨/패스, 결제 취소 후 거래로 옮긴 자산, CS 기한·증빙/전자영수증을 정한다. 세금/VAT·매출/선수금 처리는 세무사 확인.
- **삭제와 보존은 분리:** 법정 보존이 필요한 계약/결제/민원 증빙과 불필요한 개인정보를 구분한다. 기존 다수 테이블은 `auth.users` 삭제 시 cascade되므로 단순 계정 삭제로 결제 증빙까지 없애지 않도록 설계한다. 반대로 ‘장부 보존’을 이유로 모든 개인정보를 영구 보관하지 않는다.
- **이용자 보호/권리:** 닉네임·조직 소개·거래 글 등 사용자 입력의 신고/차단·부적절 내용 처리, 서비스 변경·종료 시 남은 유료 잔액/유료 권리 처리, 계정 도용·분쟁/제재 이의신청을 운영정책에 포함한다.

## 6. 인프라/운영 기준 — 현재 설정으로 착각하지 말 것

- **호스팅:** 현재 `wrangler.jsonc`와 `build:staging`은 테스트 전용이고 robots/noindex도 포함한다. 운영용을 따로 만들어 `tcg.mbbs.kr`/운영 Supabase만 연결하고 SQL/tools/docs/seed를 배포하지 않는다. staging 설정을 이름만 바꿔 그대로 배포하지 않는다. 운영 HTML은 재검증, 해시 자산은 버전 캐시, API/결제/개인 결과는 공유 캐시 금지.
- **iPhone 영상 주의:** 11/08 열람 Cloudflare Static Assets 공식 문서는 Range 요청에 기본적으로 `206` 대신 전체 파일 `200`을 반환한다고 명시한다. 현재 staging 설정에 별도 Range handler는 없다. **영상은 Range 지원 경로(예: 검증한 Worker/R2) 또는 적합한 미디어 제공 방식을 선택하고 Safari 실기로 확인**한다. 정적 요청이 무료여도 Worker 실행/미디어 저장·요청까지 모두 무료는 아니다.
- **Supabase 용량:** Pro 공식 기본은 100,000 MAU·DB 8GB·일반 egress 250GB·cached egress 250GB·Edge 호출 월 200만 등의 사용량 할당이지 동시 사용자 보증이 아니다. 현재 compute/잔여 할당·실제 사용량은 미확인. API 무제한 표시는 무한 CPU/연결/처리량이 아니다. Realtime은 사용하는 경우에만 별도로 산정한다.
- **비용/규모:** 실제 1인당 트래픽×활성 사용자, 전투당 RPC/Edge·로그/저장 크기를 측정하고 예산 50/80/100% 알림을 제안한다. 카드/음원/영상은 현재 주로 정적 호스팅/외부 주소이므로 모두 Supabase egress로 계산하지 않는다. R2는 인터넷 egress 무료지만 저장/API 작업은 과금 가능하다.
- **복구:** Pro 일일 백업은 7일, PITR는 별도 추가 기능(공식 7일 보존 약 $100/월, 세금/추가 compute 별도 가능). PITR의 복원 선택 해상도와 RPO는 다르며 공식 문서는 최악 약 2분 RPO를 설명한다. **현재 PITR 활성화는 확인하지 않았다.** DB 백업에 Storage 실파일은 포함되지 않는다. Edge 코드/배포 설정/미디어·운영 문서도 별도로 복원 가능해야 한다.
- **실제 훈련:** 제안 목표 RPO≤5분/RTO≤1시간은 서비스 규모·비용과 협의하고 실제 복구로 확인한다. PG 결제는 DB 복원만으로 취소되지 않으므로 복구 후 외부 PG와 주문/지급을 대사한다. 보안 적용 후 옛 JS만 되돌리면 안 된다. 점검/모드 중단 스위치·동일 버전 forward-fix·검토한 복원 절차를 문서화한다.
- **감시/운영 권한:** 사이트/로그인/전투 검증/결제의 가용성·p95·실패율/재시도·원장 불일치·비정상 재화 유입을 감시하고 알림 수신자를 정한다. GitHub/Supabase/Cloudflare/PG 운영자 MFA·최소 권한·키 교체를 확인한다. 실사용 JWT/비밀키/상세 개인정보를 Sentry/GA/일반 로그에 보내지 않는다.
- **최근 전환 잔여 정리:** 이번 운영 SQL은 원래 권장한 11/08 22:00 KST 토벌 정산보다 먼저 적용됐다. 옛 토벌 진행 있던 2개 조직의 미수령/주간 처리와 기록 재시작 공지는 장부를 보고 별도로 확정해야 한다. 원본 보존과 v4 자동 이월은 다른 일이다. 이 검토에서 보상 지급/회수는 하지 않았다.

## 7. 다음 작업 추천 TOP 5

1. **등급·상업 이용 권리·PG 게임업종 심사를 먼저 확인** — 심사/권리 문제는 개발 완료 뒤 알면 일정을 통째로 되돌릴 수 있다. 약관/개인정보/확률/환불·사업자정보 준비를 병행한다.
2. **보안 후속 범위 확정 후 스토리/탑/특강 재현 + 도감/MVP 영수증 연결** — 유료 재화가 들어오기 전에 보상 위조·지급 보류를 끝내거나 제공 범위를 명확히 한다. 실제 2계정·동시성·다계정 악용 점검도 포함한다.
3. **Cloudflare 운영 이전을 staging에서 리허설하고 iPhone/Android 실기로 통과** — 영상 Range, 로그인 복귀, 느린 LTE, 연속 전투·백그라운드 복귀, 낮은 연출 모드를 함께 확인한다.
4. **젬 충전 1개 상품으로 결제/미지급 복구/전체·부분 환불/PG 대사 완주** — PG는 하나만 선택하고, 패스/스킨은 서버 권리 모델을 공유하도록 설계한다. 실결제/환불 시험은 별도 승인을 받아 진행한다.
5. **소규모 CBT + 운영 모의훈련을 런칭 게이트로** — 법적 테스트 요건 확인 후 10~30명/약 7일을 제안한다. 첫 플레이 성공·D1/D7·오류·보상 중복·성능·CS/복원 결과로 GO/NO-GO를 결정하며 지금 자동 모집/예약/실행하지 않는다.

**정리:** 콘텐츠는 이미 CH0~15와 다양한 반복 모드가 있다. 지금은 분량보다 **정상 플레이 보상이 확실히 저장되고, 결제 사고를 복구할 수 있고, 폰에서 끊기지 않는 상태**가 상용 런칭의 가장 큰 보완점이다.
